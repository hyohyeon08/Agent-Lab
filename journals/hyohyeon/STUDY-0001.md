# STUDY-0001 개인 분석

## 관찰 결론

1. 결과는 같지만 과정은 동일하지 않았다.
   - 간단한 작업이라도 Agent는 결정론적 프로그램처럼 항상 같은 경로로 동작하지 않으며, 실행마다 탐색과 검증 과정이 달라질 수 있다.
   - 이번 5회 실행은 모두 같은 기능 결과와 구현 지점에 도달했지만, 파일 탐색 방식, 도구 호출 구성과 공개 테스트 범위에는 차이가 있었다.

2. 토큰 수만으로 Agent의 효율을 평가하면 안 된다.
   - 토큰 수에는 공통 실행 Context와 cached input이 포함된다.
   - 실행 시점과 인프라 조건도 다르므로 토큰 수나 실행 시간 하나만으로 효율 순위를 정하기 어렵다.

## 후속 가설

Tool Call 수 자체보다 Model과 Tool 사이의 왕복 구조가 토큰 효율에 더 큰 영향을 줄 수 있다.

- RUN-0002와 RUN-0004는 논리 Tool Call이 각각 9회로 같았다.
- RUN-0002는 상위 Tool Call 봉투 5회, 모델 요청 프록시 6회, 총 101,366 tokens를 기록했다.
- RUN-0004는 상위 Tool Call 봉투 8회, 모델 요청 프록시 9회, 총 157,015 tokens를 기록했다.
- Agent 최적화의 핵심은 단순히 Tool Call 수를 줄이는 것이 아니라, 관련 조회와 검증을 적절히 묶어 Model과 Tool 사이의 왕복을 줄이는 데 있을 수 있다.

이 비교는 가설의 출발점일 뿐 인과관계를 증명하지 않는다. 각 Tool Call의 내용과 반환량이 다르고, RUN-0002~RUN-0005가 동시에 실행됐다는 조건도 고려해야 한다.
